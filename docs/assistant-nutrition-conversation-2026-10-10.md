# 식단 상담의 후속 대화와 표 표시 수정 — 2026-10-10

## 재현한 문제

체지방 감소 목표 → 하루 두 끼·집에서 식사·선호/알레르기 없음 → “표로 만들어줘” → “아니 식단”의 4턴 대화에서, 마지막 질문에 식단 키워드가 없으면 운동용 지침과 회원의 운동 분석이 다시 입력됐다. 등록 목표보다 운동 분석의 근비대 목표가 앞서거나 운동 기록표를 만드는 문제가 있었다. 답변 표시 컴포넌트도 Markdown 표를 지원하지 않았다.

## 수정

- 기존 회원별 대화 문서에 nutrition 맥락을 보존한다. 사용자 발언(최대 최근 16개), 명시한 목표·끼니 수·장소와 표 형식을 다음 질문에도 전달한다. AI의 이전 추정을 사용자 사실로 요약하지 않는다.
- 식단 상담에는 무관한 운동 기록·분석·파생 목표를 입력하지 않는다. 실제 운동 기록 분석을 명시적으로 요청하면 원래 운동 대화로 전환한다. 새 회원/새 대화는 기존 대화를 참조하지 않는다.
- 이전 버전의 오염된 대화는 읽을 수 있는 최근 사용자 발언에서 복구하고, 운동 기록을 사용한 이전 AI 응답은 식단 맥락에 재입력하지 않는다. DB 대화를 삭제하거나 일괄 변경하지 않는다.
- 모델 출력 형식이 짧은 결론을 요구하면서 동시에 Markdown 표를 요구하던 충돌을 해소했다. 식단표를 요청하면 끼니·메뉴·대체 방법을 필수 구조화 배열로 받고 서버에서 표로 변환한다.
- 실제 답변 컴포넌트에 표 헤더/셀과 키보드 접근 가능한 내부 가로 스크롤을 추가했다. 모델 HTML은 그대로 비활성 텍스트로 남는다.

## 검증

- 단위·렌더링 34개, Firestore 에뮬레이터 서비스 110개 통과. 타입 검사 통과.
- `node scripts/evaluate-nutrition-conversation.mjs --live --firebase-key`: 합성 사례로 기본/심층 각각 4턴, 총 8회 실제 생성. 실제 회원 데이터는 사용하지 않는다. 기본 실행은 유료 호출 없이 문맥만 검증한다.
- 최종 실제 생성 결과: 두 모드 모두 최초 조건 확인 질문 1개, 이후 추가 질문 0개. 체지방 감소·두 끼 가정식을 유지하고, 표 요청과 정정 모두 식단표로 출력. 무관한 운동 인용 0개. 심층은 표 변환 시 앞서 제안한 메뉴를 유지했다.
- 실제 생성한 표를 제품 렌더러/CSS로 Chrome에서 확인. 400px 화면에서 페이지 폭/스크롤 폭은 모두 400px이며, 표의 420px 내용만 362px 컨테이너 안에서 가로 스크롤된다.

## 남은 품질 한계

이번 검증은 대화 주제·조건·형식 유지에 대한 것이다. 개인 필요 열량/영양 충족을 검증한 식단은 아니다. 기본 모드에서는 특정 시간 간격 권고와 불필요한 탄수화물 제한 같은 일반화가 여전히 관찰됐다. 음식 대체 분량과 조리 전후 기준도 모든 답변에서 일관되지는 않다. 따라서 이 수정이 식단 내용 전반의 정확성까지 보장한다고 해석하면 안 된다. 영양 품질 평가와 별도 개선이 필요하다.

과거 사용자 조건이 이미 서버의 최근 대화 창 밖으로 사라진 경우에는 이를 만들어 복원하지 않는다. 보존하는 사용자 발언도 유한하므로 긴 대화에서 명시적 제한 조건을 더 체계적으로 유지하는 것은 후속 과제다.
