# 전문가 판단 원칙의 실행 구현

2026-09-11. 원본 설계: `EXPERT_JUDGMENT_PLAN.md`. 이번 변경은 서버 코드와 UI 구현이며 서버 배포 완료를 의미하지 않는다.

## 원칙과 코드의 연결

| 설계 원칙 | 구현 |
| --- | --- |
| 조건이 같아야 비교 | `functions/judgment.mjs`의 `validateCriteria`, `recordSignature`, `evaluateJudgment`. 트레이너가 기구·중량 표기·좌우·세트 목적 확인. 기록 값 또는 목표 변경 시 재확인 필요 |
| 진행 유지 후보 | 동일 운동·중량의 날짜별 최고 반복 횟수를 서버에서 계산. 다른 중량과 부위 볼륨을 진행으로 합산하지 않음 |
| 정체 검토 후보 | 트레이너가 입력한 관찰 일수·최소 수업 횟수·목표 반복 횟수 사용. 날짜별로 집계하여 같은 날 여러 기록을 여러 수업으로 세지 않음. 기준 미입력은 판단 보류 |
| 계획 이탈 확인 | 기준 저장 시 계획 스냅샷 보존. 계획 저장일 다음 날 이후로 지정한 실제 수업의 종목별 세트 수와 비교. 기록 부재를 미수행으로 단정하지 않음 |
| 목표 판단 자료 부족 | 목표·판단 기준·비교 가능한 측정 기록이 없는 이유를 반환. 이 구현의 수행 지표가 체중 변화 등 회원 전체 목표를 대체하지 않음 |
| 근거 있는 리포트 | `REPORT_PROMPT`에 `JUDGMENT_PROMPT` 결합. 서버 적용 조건을 Gemini가 바꾸지 못하도록 상태·카드 ID/버전·기록 ID·참고 사례 ID 검증 |
| 트레이너 선택 축적 | `saveJudgmentDecision`: 유지/조정/추가 확인, 이유, 대안, 판단 변경 조건, 다음 지표·날짜, 당시 리포트·기준·기록 스냅샷 |
| 후속 결과 연결 | `saveJudgmentOutcome`: 원래 판단을 덮어쓰지 않고 별도 결과 문서에 관찰 날짜·기대와 다름/기대한 변화/불명·메모·해당 날짜 기록 저장 |
| 다음 분석에서 재사용 | 해당 트레이너·회원의 최근 판단 20건 중 운동이 관련되거나 일반 확인인 사례 최대 5건 선택. 사례마다 최근 후속 결과 최대 2건. 참고한 사례를 리포트에 표시 |
| 과거 판단과 미래 결과 분리 | 당시 판단 스냅샷 불변. 결과는 별도 컬렉션. 아직 관찰하지 않은 미래 날짜 저장 거부, 분석 시점 이후의 사례/결과 검색 제외 |
| 비용·캐시 | 판독 호출 재사용. 리포트는 기존 분석+프로그램 한 번의 호출 안에서 생성. 기준·사례·결과·수정 이유·계획까지 캐시와 작업 완료 시 최신성 검증에 포함. 원가 한도 유지, 서버용 비교 해시는 Gemini 입력에서 제외 |
| 소유자 분리 | `judgmentSettings`, `judgmentDecisions`, `judgmentOutcomes`는 회원 소유자만 읽고 브라우저 직접 쓰기는 금지. Auth + App Check가 적용된 기존 callable을 통해 저장 |

## 화면

`src/components/judgment-report.tsx`, 진행 분석의 요약 탭 안에 표시한다.

- 내 판단 기준 설정(선택): 첫 구현은 일반 성인 PT의 **중량 운동 한 종목·고정 중량의 반복 횟수** 지표. 트레이너가 직접 입력하며 최소 수업 횟수·기간을 자동 채우지 않는다.
- 카드별 관찰 / 해석 / 질문 / 다음 행동, 필요한 정보 및 원본 근거.
- 내 판단 저장 → 후속 결과 저장 → 다음 분석에 반영. 입력은 선택 사항이며 업로드 뒤 분석을 막는 필수 승인 단계가 아니다.
- 판단 카드는 명시적으로 `draft`. 전문가 합의·검증·예측 정확도를 주장하지 않는다.

## 아직 구현/검증하지 않은 범위

- 모델 가중치 재학습/미세조정 없음. 저장된 사례를 입력에 제공하는 문맥 기반 재사용이다.
- 검토된 다수 전문가 사례집, 전문가 간 이견 평가, 실제 정답/성과 검증은 아직 수집하지 않음. 코드의 조건 검사는 전문가 검증을 대체하지 않는다.
- 다른 회원/센터의 자료 공유 검색 없음. 개인정보 동의 기반 비식별 지식 공유는 별도 작업.
- 체중·체지방·유산소·재활·강도 지표를 위한 판단 카드, 여러 운동 목표의 동시 기준 관리, 목표 달성 확률 예측은 미구현.
- 평가 시점을 선택하는 과거 리포트 재현 UI/독립 검증 도구는 미구현. 사례 검색의 시점 필터를 그 도구의 완성으로 보지 않는다.
- 실제 Gemini는 아직 배포 전이므로 본 변경의 UI/서비스 테스트는 모델 응답 대역을 사용했다. 실제 모델의 판독·판단 정확도를 입증하지 않는다.

## 검증

`npm run test:all`: 기존 파일·기록·보안 회귀 + 카드 조건·목표/기록 변경·중량 구분·관찰 기간·잘못된 인용 거부·판단/결과 저장 및 재사용·캐시·소유자 권한.

추가 에뮬레이터 브라우저 검증: 업로드 후 원본/분석 전환, 기준 설정, 선택 이유, 기대와 다른 후속 결과, 다음 리포트의 사례 포함, 원본 판독 호출 횟수 불변, 모바일 가로 넘침 없음.
