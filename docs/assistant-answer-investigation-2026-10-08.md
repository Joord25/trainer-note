### 확인한 원인

같은 '지난달 허리 불편, 오늘 상태 미기록' 질문을 실제 두 모드로 재생성했다. 기본은 상태 확인 전 머신이 더 안전하다고 제안했고, 심층은 조건별 방향을 말했으나 세 번째 항목이 '특정 운동을 강제하지 않는다'는 자기 제한 설명이었다. 기존 프롬프트의 제안 지침은 선택지·이유·조건을 요구했지만, 실제로 물어볼 말과 그 답에 따른 진행 절차를 충분히 구체화하지 않았다. 후속 질문 규칙도 가상 사례에서 회원에게 할 질문과 질문자에게 필요한 추가 질문을 구별하지 않았다.

### 변경

- 수업 대응 질문은 확인할 말 → 결과별 행동 → 진행 중 유지·조정·중단 기준으로 설명한다. 계산·개념 질문에는 이를 강제하지 않는다.
- 가상 사례의 질문 예시는 답변 본문에 넣고, 질문자를 회원으로 간주해 질문 칩으로 되묻지 않는다. 이미 주어진 현재 상태와 워밍업 결과를 출발점으로 사용한다.
- 조건이 충분한 실제 루틴 요청과 현재 상태가 불명확한 조건별 진행안 요청을 구분한다. 구체적 답변을 위해 근거 없는 운동명·중량을 만들어내지 않는다.
- 심층에는 선택 이유와 판단을 바꾸는 반응을 연결하도록 하고, 피로 사례 예시로 설명 흐름을 보여준다. 출력의 번호·제목·설명 형식, 모델 설정, 비공개 보호와 기록 접근 경계는 변경하지 않았다.

개인 상태와 능력에 맞춘 활동/운동 선택 원칙은 [NICE NG59](https://www.nice.org.uk/guidance/ng59/chapter/recommendations)를, 허리 통증과 양측 다리 힘 빠짐·배뇨 변화가 함께 있을 때 응급 평가가 필요하다는 기준은 [NHS Back pain](https://www.nhs.uk/conditions/Back-pain/)을 확인했다. 이 확인을 모든 답변에 기관명 인용을 강제하는 규칙으로 넣지는 않았다.

### 검증과 한계

- 채팅·검색 회귀 검사 32개 통과, 서버/평가 스크립트 구문 검사 및 diff 공백 검사 통과.
- 수정 전 2개, 1차 수정 후 12개, 최종 12개: 총 26개 실제 API 응답. 실제 회원 자료나 Firestore 조회는 사용하지 않았다.
- 최종 6개 사례 × 두 모드: 상태 미확인, 이미 상태 확인됨, 수면 부족, 명시적 긴급 증상, 기존 수행 능력/볼륨 구별, 비공개 모델 정보 문의.
- 최종 상태 미확인 사례는 두 모드 모두 회원에게 할 질문을 본문에 제시하고 준비 세트와 불편에 따른 조정 행동을 설명했다. 가상 사례를 질문자 개인의 상태로 바꾸는 후속 질문은 최종 12개 모두 없었다. 비공개 요청은 두 모드 모두 검색 차단 및 비공개 답변을 반환했다.
- 의미 품질은 완전 통과로 표시하지 않는다. 상태 미확인 기본 답변은 지속/악화 시 전문가 안내가 빠졌고, 심층도 분기별 이유를 더 충분히 설명할 여지가 있다. 현재 상태 확인됨 사례는 준비 세트를 반복하는 표현이 일부 남았다. 긴급 사례는 응급 평가를 우선했으나 진단 가능성을 과하게 표현했다. 기존 볼륨 해석의 심층은 요청하지 않은 한계 확인 권고를 붙였다. 길이나 JSON 검증 성공을 의미 품질 보증으로 삼지 않는다.

## v24: 배포 마무리 및 실제 기록 전환 수정

사용자가 반복 점검을 직접 하는 대신 에이전트가 검증과 배포까지 완료하도록 요청했다.

### 최신 스크린샷의 재현 원인

가상 사례/일반 지식 대화 뒤 `현재 러닝머신 기록을 참고해서 ...`라고 요청해도 `requestsMemberContext`가 운동명이 들어간 기록 전환 표현을 인식하지 못했다. `prepareChatFacts`가 이전 가상 범위를 유지해 실제 records를 비웠다. 동일 문장으로 회귀 검사가 실패하는 것을 확인한 뒤, 현재/최근/저장된 기록과 운동명·계획 수식어가 함께 있는 전환 표현을 인식하도록 수정했다. 가상 후속 질문의 기록 격리 검사는 유지했다.

- 기본·심층 모두 실제 기존 운동 구간을 확인하고 인용한 뒤 대안별 목적·차이·선택 기준을 설명하도록 안내를 보완했다.
- 신경 증상 뒤 단순 중량/범위 조정으로 재시도하는 문구가 섞이지 않도록 조정 분기와 의료 평가 분기를 구분했다.
- 기존 분석 탭/기간 선택 디자인 통일, 다음 기간 방향의 기록 요약 스타일 통일, 채팅 입력 직후 로컬 질문 표시와 즉시 스크롤 수정도 이번 배포에 포함한다.

### 검증

- 전체 회귀: 475개 중 474 통과, 1 건너뜀, 실패 0. Firebase 에뮬레이터에 필요한 Java를 설치된 OpenJDK 24로 지정했다.
- 마지막 범위 수정 후 채팅/검색 33개 통과. 가상/일반 → 실제 기록 전환과 반대 방향의 기록 격리를 검증했다.
- 대화 연속성 합성 검사 10개 통과. TypeScript 검사와 git diff 공백 검사 통과.
- 실제 API 합성 평가 22개를 읽고 검토했다. 마지막 수정 후 상태 확인됨/긴급 증상/실제 러닝머신 기록 전환 6개를 추가 검토했다. 실제 회원 자료는 이 API 평가에 사용하지 않았다.
