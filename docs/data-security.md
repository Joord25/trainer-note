# 현재 데이터 보안 범위

`.env.local`은 암호화 파일이 아닙니다. Git에서 제외되어 있고, 로컬 권한은 파일 소유자만 읽고 쓰는 0600입니다.
현재 들어 있는 값은 Firebase Web SDK 공개 설정 6개이며, `NEXT_PUBLIC_` 변수는 클라이언트 번들에 포함됩니다.
Firebase API key는 프로젝트 식별용이며, 회원 데이터 권한은 Auth와 Firestore Security Rules로 제어합니다.
공식 안내: https://firebase.google.com/docs/projects/api-keys

현재 적용한 규칙은 회원, 직접 확인한 운동 기록 및 PDF 연결 정보를 위한 초안입니다. 다른 로그인 UID 및 비로그인 사용자의 회원 조회/생성/수정/삭제를 거부하며, 허용 필드·길이·타입·타임스탬프도 검증합니다.
에뮬레이터 테스트 69개를 통과했지만 전체 서비스에 대한 보안 보증은 아닙니다. 지원 데이터 종류가 늘어나면 규칙과 테스트를 같이 확장해야 합니다.

- 회원 캐시는 기본 메모리 캐시만 사용합니다. Firestore 디스크 지속 캐시는 활성화하지 않았습니다.
- Auth 로그인 상태는 브라우저에 유지되므로 공용 기기에서 로그아웃해야 합니다.
- AuthGate는 화면 전환이며 서버 API 권한 검증을 대신하지 않습니다. 이후 서버 엔드포인트는 ID 토큰 검증이 필요합니다.
- Gemini API 키·서비스 계정 비밀 키는 서버 전용이며 NEXT_PUBLIC 변수나 Git에 넣지 않습니다. 현재 앱에는 둘 다 연결하지 않았습니다.
- App Check와 API 키 제한 범위의 개별 감사는 아직 완료하지 않았습니다. 공개 출시 전 추가 확인 대상입니다.
- Storage 원본 저장 코드와 소유자·크기·MIME·예약 문서 검증 규칙을 구현했습니다. 운영 버킷 미생성으로 Storage 규칙 배포는 아직입니다.
- 파일 목록과 회원 fileCount 변경을 같은 트랜잭션으로 제한하고, 파일이 남은 회원 삭제를 서버에서 거부합니다.
- Storage 파일 덮어쓰기와 메타데이터 변경을 막습니다. 삭제는 소유자에게 허용해 연결 문서가 누락된 원본도 정리할 수 있습니다.
- PDF 헤더 검사 및 MIME 검증은 악성 파일 탐지나 완전한 PDF 구조 검증이 아닙니다. 추후 판독 서버에서 파일을 다시 검증해야 합니다.
- 파일의 SHA-256과 ready 상태는 클라이언트가 작성합니다. AI 처리 서버는 이를 신뢰하지 않고 원본 해시·파싱 결과를 재검증해야 합니다.
- 앱은 공개 다운로드 토큰 링크를 만들거나 저장하지 않고 인증된 getBlob을 사용합니다. 사용자가 내려받은 파일은 로그아웃으로 회수되지 않습니다.
- Storage와 Firestore 사이에는 원자적 트랜잭션이 없습니다. 중간 실패는 uploading/deleting 상태를 보존해 재확인·삭제를 지원하며, 운영 시 오래된 미완료 항목과 원본 대조가 필요합니다.

### 직접 확인한 기록

- records 경로에도 로그인 UID와 회원 존재 여부를 검사합니다. 생성/삭제 시 부모 recordCount와 원자적 갱신을 요구합니다.
- 허용 필드, 날짜 범위, 주 부위, 중량 유형, 최대 8세트 각각의 kg/횟수, 원본 해시/페이지, 서버 시각을 검증합니다.
- 외부 중량은 양수, 맨몸·중량 미상 kg는 null입니다. 알 수 없는 무게를 0으로 기록하지 않습니다.
- 수정 revision은 1씩 증가해야 하고 원본 해시·이름 및 생성 시각을 바꿀 수 없습니다. 클라이언트도 트랜잭션에서 기존 revision을 비교합니다.
- 원본 PDF는 로컬 Blob URL로만 표시하고 화면을 닫으면 해제합니다. 문서 내용은 아직 AI에 전송하지 않습니다.
- 파일명·해시·페이지와 ‘직접 확인’ 상태는 트레이너가 제공한 정보이며 서버가 원본 내용의 정확성을 보증하지 않습니다.
- 현재 기록은 횟수 기반 운동만 지원합니다. 시간·거리·좌우 개별 기록, 변경 이력 보관, 자동 판독 검증은 후속 범위입니다.
