# 목표 설계와 수업 평가

목표 설정 첫 단계의 자유 설명을 AI가 목적 분류, 단계 목표, 확인된 초기 상태, 목적별 평가 방법·누락 근거로 정리한다. AI 제안은 goalProposals에 원문과 함께 보존하고, 트레이너가 초안을 반영·수정한 후 목표를 저장한다. 숫자 목표·기간·실제 측정값은 임의 생성하지 않도록 요청하며, 최종 적용은 트레이너 확인을 거친다.

## 트레이너 맥락

- trainingGoalHistory: AI 원안, 확정 목표, 수정 여부와 판단 이유. 해당 회원의 다음 제안에 참고.
- trainingPrinciples: 트레이너가 직접 입력하고 다른 회원에게도 참고하도록 선택한 일반 기준. 같은 트레이너 계정에서만 참조하며 온보딩의 ‘참고 해제’로 제거 가능.
- assessmentDecisions: 실제 평가 해석에 대한 동의·수정·보류와 이유. 해당 회원의 다음 목표·평가 해석·수업 제안에 참고.
- 모델 파인튜닝이나 검증된 전문 지식의 자동 습득이 아니라, 서버에 저장된 확정 맥락을 후속 모델 요청에 제공하는 방식. 과거 판단 자체를 성공 증거로 취급하지 않음.

## 수업 결과

평가 초안의 fields에 수치 지표 이름·단위·방향·선택 목표값을 정의하고 트레이너가 확인한다. 이전 목표에는 수치 지표를 직접 추가할 수 있다. 수업마다 날짜·수치·실제 수행 조건·중단 지점/이유·선택 체감 강도/관찰을 저장한다.

평가 이름·구간·비교 조건·지표 이름/단위로 protocolKey를 만들고, 실제 수행 조건 문자열이 같은 기록끼리만 비교한다. 조건 문자열은 공백 정규화나 의미 추정으로 합치지 않음. 동일 날짜·프로토콜·조건은 하나의 기록으로 저장하며 수정은 revision 검사 및 별도 이력 보존. 목표값 변경만으로 측정의 비교 가능성은 깨지지 않으나 목표 평가에는 현재 목표와 적용 기간을 사용한다. 목표 적용일 미정이면 목표 대비 AI 해석을 보류한다.

같은 조건의 다른 날짜 기록 2회 이상에서 AI 해석을 요청한다. 기록 범위·현재 목표 버전·각 기록 버전으로 캐시하며, 생성 도중 또는 판단 저장 전에 기록이 바뀌면 재확인을 요구한다. AI 해석의 동의/수정/보류는 트레이너 이유와 함께 저장한다. 누락값은 0이 아니며, 수치 목표 충족과 전체 훈련 목적 달성을 구분한다.

## 범위와 검증

모든 쓰기는 기존 App Check/로그인/회원 소유권을 확인하는 trainerAi 경로를 사용한다. 클라이언트는 본인 회원의 문서만 읽을 수 있다. 목표 저장은 다음 수업 분석 갱신을 요청하며, 새 목표·평가·판단이 리포트 캐시 입력에 포함된다. 읽기 맥락은 최근 평가 40개·목표 판단 5개·평가 판단 5개·일반 기준 20개로 제한. 개별 목표 평가 해석은 선택 범위 최대 120회. 회원당 평가 기록 최대 500개.

검증: 공유 타입 검사, 데이터 검증·조건별 비교 단위 테스트, Firestore 에뮬레이터에서 저장/개인화 격리/권한/캐시/경합 테스트, 실제 React 컴포넌트를 사용하는 격리 UI에서 목표부터 평가·판단 저장까지 확인. UI 모델 응답은 테스트 응답을 사용하며 운영 회원에 테스트 측정값을 저장하지 않음.

## 운영 배포 확인

함수 코드베이스는 `trainer-ai`. 개별 함수 배포 시 코드베이스까지 지정한다.

```sh
firebase deploy --only functions:trainer-ai:trainerAi,functions:trainer-ai:buildMemberReport --project trainer-note-a9dd7
```

배포 도구의 성공 상태만으로 적용 완료를 판단하지 않는다. CLI에서 두 함수의 `Successful update operation`을 확인하고, 운영 앱의 `AI로 목표·평가 정리` 요청으로 실제 응답을 확인한다. `지원하지 않는 요청` 오류는 모델의 문장 해석 실패가 아니라 함수의 action 라우팅 거절이다.

Gemini 요청 스키마의 enum에는 빈 문자열을 넣을 수 없다. 평가 sourceId는 STRING으로 전달하고, 응답의 허용 출처 검증은 서버의 validateAssessmentDraft에서 유지한다. 토큰 계산 API의 요청 거절과 입력 토큰 상한 초과는 서로 다른 오류로 표시한다.

## 추가 답변과 저장 안내

온보딩의 목표/평가 추가 답변은 편집 중인 입력과 제출 이력을 분리한다. 성공 시에만 입력을 비우며, 실패 시 작성 내용을 유지한다. 질문·답변 이력은 다음 호출과 목표 적용에 보존하며 누적 2,000자 초과 시 조용히 잘라내지 않고 정리를 요청한다. 고정 운동 예시 대신 현재 질문에 답하도록 중립적인 입력 안내를 표시한다.

두 AI 스키마 모두 질문 최대 2개. 필수 누락 조건만 함께 확인하고, 선택적 측정 권유나 이미 답한 질문을 반복하지 않도록 지시한다. 대화 횟수 자체를 고정하지 않으며, 조건이 충분하면 질문 없이 종료한다. 각 답변 반영 버튼 클릭이 생성 요청 한 번에 해당한다.

AI 제안 변경 후 조정 이유 누락은 일반 AI 장애가 아니라 입력 검증 오류다. 구체적인 안내와 이유 입력란 포커스를 제공한다. 변경 없는 초안은 이유 없이 저장 가능함을 Firestore 에뮬레이터에서 확인한다. 추가 답변 UI의 성공/실패/연속 답변/초안 반영은 모의 응답을 연결한 실제 React 컴포넌트로 검증한다.
