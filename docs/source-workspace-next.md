# 원본 비교 작업 화면 — 2026-09-11 사용자 요청

## 적용한 원본 뷰어

- 여러 PDF와 PNG/JPEG를 파일별로 구분하여 한 스크롤에 이어서 표시한다.
- PDF 내부 페이지를 직접 렌더링한다. 파일별 iframe 안에서 다시 스크롤하지 않는다.
- 원본 선택은 해당 위치로 이동한다. 분석 근거의 원본 파일·페이지 연결을 유지한다.
- 원본은 기존 인증된 Storage 읽기를 이용한다. 화면 구성을 위해 파일을 병합하거나 AI를 호출하지 않는다.
- PDF.js 런타임은 고정된 npm 버전과 같은 worker·폰트·CMap·WASM을 로컬에서 제공한다. `postinstall`, `predev`, `prebuild`에서 준비한다.
- 가까운 파일부터 불러오며 화면에서 먼 PDF 페이지의 캔버스는 해제한다. 뷰어 종료 시 Blob URL과 PDF worker를 정리한다.

검증: 실제 AnalysisSource 컴포넌트를 가상 원본(PDF 3쪽 + PNG + PDF 2쪽 + JPEG + 손상 PDF)으로 브라우저 실행. 파일 간 스크롤, 위치 이동, 근거 2쪽 이동, 확대/너비 맞춤, 개별 오류/재시도, 390px 화면, React StrictMode에서 종료 후 Blob URL 정리 통과. Next production build 통과. 실회원 파일을 테스트용으로 변경하지 않았다.

## 추가로 요청한 구조 — 아직 구현 전

사용자는 2뷰/3뷰의 의미를 다음과 같이 변경하기를 원한다.

- 2뷰: 왼쪽 연속 원본 + 가운데 작업 영역.
- 가운데 작업 영역: `기록 수정 / 진행 분석 / 다음 수업` 탭. 기록 수정에서는 원본과 추출된 기록을 동시에 보며 바로 수정한다.
- 3뷰: 위 두 영역 + 오른쪽 AI 도우미 채팅.
- 분석·수업 준비 탭은 현재 구현한 실제 집계·Gemini 분석·수업 계획 기능을 유지한다.
- 상단은 한 줄의 최소한의 회원/파일·보기 전환 도구로 줄이고, 원본·작업 영역 높이를 넓힌다.
- 탭 변경으로 원본을 다시 다운로드하거나 PDF를 다시 준비하지 않도록 뷰어를 유지한다.
- 도우미는 해당 회원의 현재 업로드 일지에 근거해 답변한다. 원본의 선택 영역(올가미/영역 선택)과 파일·페이지를 질문에 연결한다. 분석 근거를 클릭하면 원본 위치를 찾아갈 수 있어야 한다.
- 채팅은 기존 인증·회원 격리·토큰/원가 예산 제한을 적용하는 서버 기능으로 구현해야 한다. 버튼만 있는 목업으로 완료 처리하지 않는다.

## 복합 기록 자동 분리 — 아직 구현 전

- 예: `Cable curl + ext.` 한 행에 두 운동과 대응하는 반복 수가 명확하면 운동별 기록 2개로 만든다.
- 예: `Cable lying ext + DB curl`, kg `20/5`, rep `8/10`이면 왼쪽·오른쪽 수치를 각각 대응한다. 20kg·5kg를 양쪽 운동에 복제하지 않는다.
- 공유한 원본 파일·페이지·원문 행, 슈퍼세트/묶음 관계를 보존한다.
- 스쿼트·스러스터 같은 단일 복합관절 운동이나 좌우 표기는 운동 2개로 나누지 않는다.
- 운동명 또는 무게·횟수의 대응이 불분명하면 값을 만들어 확정하지 않는다. 해당 부분만 수정 화면에서 확인하도록 표시한다.
- OCR 스키마·프롬프트, 서버 검증, 집계 중복 방지, 수정 UI를 함께 검증한다.
- 이미 저장한 판독 결과에 일괄 재판독/유료 호출을 실행하지 않는다. 기존 결과의 재처리는 범위와 비용을 별도로 정한 뒤 적용한다.
