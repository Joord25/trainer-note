# 날짜별 판독 프롬프트 비교 테스트

이번 변경: workout-v11-session-coverage. 모델은 gemini-3.1-flash-lite로 유지한다. 날짜별 분할 요청이나 자동 재시도는 아직 추가하지 않는다. 기존 1회 요청에서 지시와 응답 형식을 개선한 효과를 먼저 측정한다. 구독·추가결제 설정과 진행 분석의 입력량 제한은 이번 변경 범위가 아니다.

## 1. 준비

- Hosting과 Functions를 모두 배포한다. Hosting만 배포하면 새 판독 프롬프트가 반영되지 않는다.
- 실제 회원과 별도로 테스트 회원을 만든다. 기존 회원에서 재판독하면 확정·저장 기록 보존 로직 때문에 새 응답과 과거 기록이 섞일 수 있다.
- 이전에 문제가 생긴 동일한 손글씨 사진을 사용한다. 해상도·잘라내기·파일 내용은 바꾸지 않는다.
- 사진을 보고 날짜별 운동 원문 목록을 미리 적는다. 애매한 날짜와 약어는 확정하지 말고 후보로 표시한다. 연도·중량·횟수가 없는 경우 빈 값이 정답이다.

기존 비교 기준: 운영 응답은 앞의 두 날짜 영역에서 운동 7개만 반환했고, 1/21 이후를 unparsed 한 항목으로 생략했다. 입력 3,965 / 출력 1,499토큰이었다. 화면에서 읽힌 1/17이라는 날짜 자체도 원본과 대조해야 한다. 기존 결과는 정확도 정답이 아니다.

## 2. 실행

1. 테스트 회원에 사진을 한 장만 업로드한다.
2. 기록 수정에서 판독이 끝날 때까지 기다린다.
3. 상단에 **날짜별 판독 현황**, **workout-v11-session-coverage**가 표시되는지 확인한다. 안 보이면 Functions 배포 또는 재판독 여부부터 확인한다.
4. 원본의 첫 날짜부터 마지막 날짜까지 현황 목록과 대조한다. 숫자만 맞는지 보지 말고 날짜별 운동 원문도 확인한다.
5. 각 날짜를 펼쳐 읽은 원문과 상태, 운동 반환 수/발견 수를 확인한다. 운동 카드에서도 날짜와 종목 소속을 확인한다.
6. AI로 다시 판독을 눌러 동일 사진을 총 3회 비교한다. 테스트 중 운동을 확정·수정하지 않는다. 현황은 마지막 AI 응답 기준이고 기존 저장 기록은 유지될 수 있다.
7. 같은 절차로 표 형태의 다중 날짜 일지 한 장도 테스트한다.

재판독마다 AI 이용량이 발생한다. 우선 파일당 총 3회만 실행한다. 이 테스트를 위해 원본을 삭제할 필요는 없다.

## 3. 상태의 뜻

- 처리됨: AI가 발견한 운동을 모두 결과로 반환했다고 보고했고 수량 대조도 일치함. 정확성 보장이나 트레이너의 확정이 아니다.
- 일부 처리: 일부 운동을 반환했지만 남은 부분이 있거나 발견 수와 반환 수가 다름.
- 읽기 불가: 글자가 흐리거나 잘려 읽지 못한 영역.
- 미처리: 발견했지만 운동 결과로 변환하지 못한 영역.
- 세트 정보 미기록: 원본에 수치가 없다는 의미. 운동명을 버리거나 가짜 1세트를 만들면 안 된다.

AI가 날짜 영역 자체를 빠뜨리면 목록에서도 빠질 수 있다. 발견 수와 반환 수가 모두 틀려도 수량 검사는 통과할 수 있으므로 원본 대조가 필수다. 원본의 연도 미기재에 대한 기존 기본 연도 적용 동작은 이번 변경에서 수정하지 않았다.

## 5. 다음 결정

- 두 양식에서 3회씩 날짜/읽을 수 있는 운동 누락 없이 반환하면 프롬프트 개선의 1차 통과로 본다. 다른 양식에서도 계속 검증한다.
- 뒤쪽 날짜의 미처리 또는 누락이 반복되면 날짜별 분할 요청과 누락 영역 재시도로 전환한다.
- 날짜 원문은 모두 보존됐는데 운동 카드가 빠지면 변환 단계의 문제를 먼저 고친다.
- 흐릿한 부분만 읽기 불가라면 재촬영/원본 PDF로 비교한다. 판독 상태가 솔직한지와 글씨 인식 정확도를 구분한다.

현재 완료된 검증은 파서·저장·화면의 자동 테스트다. 실제 Gemini의 이번 프롬프트 품질 비교는 사용자가 위 사진으로 실행한 후 판단한다.
