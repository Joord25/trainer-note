- 분석 입력/응답: 목표·메모·기록 요약 전달, 목표 변경 캐시 무효화, 목표 설명의 개인 근거 ID와 출처 ID 검증, 임의 URL 및 근거 없는 새 중량 차단.
- 기존 흐름: 재분석·캐시·다회차 계획·저장·요청 모델/추론 설정의 관련 회귀검사.
- 화면: 합성 데이터로 ‘목표와 현재 기록’, 출처 펼치기, 식단 상담 질문 초안 연결 확인. 실제 회원 자료나 외부 전송 없이 검증. 임시 화면은 배포에서 제거.

## 실제 모델 비교

개인정보 없는 3개 합성 사례를 사용했다. 기본 모델의 응답에서는 목표 연결 누락, 기록 일관성을 수행 안정성으로 확대하는 표현이 나타났다. 추론 설정만 조정하는 것으로 충분히 해소되지 않아 기존 앱의 심층 모델을 사용하고 목표 연결을 필수 응답 항목으로 분리했다.

최종 검사 대상:

| 사례 | 관찰된 개선 | 계속 살펴볼 한계 |
|---|---|---|
| 다이어트 + 하체 저반복 + 유산소 미기록 | 목표와 저항운동 참여를 연결하고, 유산소 미기록을 별도 확인 대상으로 설명. 존재하는 대한비만학회 자료 연결 | 부위 설명에서 처음 등장한 기록을 ‘추가’라고 표현하는 경향은 남아 있음 |
| 시간 확보로 체스트 프레스 3→4세트, 같은 중량 런지 10→12회 | 세트 추가와 반복 증가를 구분하고 시간 확보 배경을 반영 | 일부 ‘안정적’ 표현은 실제 자세 평가와 구분해서 읽어야 함 |
| 기초체력 + 로우 세트 증가 + 러닝 시간 증가 + 코어 | 러닝 시간과 로우 세트를 분리하고 코어 에어 바이크를 유산소로 합산하지 않음 | 모든 주요 메모를 매번 우선 방향에 반영한다고 보장되지는 않음 |

형식 검증은 연구 해석의 정확성을 입증하는 시험이 아니다. 이번 범위는 1차 근거 기반과 데이터 연결의 검증이며 임상 검증·전체 회원군 검증이 아니다. 작은 합성 표본의 결과를 모든 응답의 성공률로 표시하지 않는다. 실제 회원에게 적용할 때에는 트레이너가 제안을 검토·수정하고, 추가 근거/사례는 동일한 기준으로 축적한다.

재현: `node scripts/evaluate-goal-coaching.mjs`는 API 호출 없이 사례 구성을 확인한다. `--live`는 선택된 합성 사례당 한 번 호출하며, 결과는 임시 디렉터리에만 저장한다. API 키나 실제 회원 데이터를 결과에 포함하지 않는다.
