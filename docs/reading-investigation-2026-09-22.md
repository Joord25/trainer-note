# 다중 날짜 일지 판독 조사 (2026-09-22)

## 확인된 사실

운영 Firestore의 해당 import에서 raw.records와 rows를 읽기 전용으로 비교했다.
- promptVersion: workout-v10-preserve-undosed-exercises, model: gemini-3.1-flash-lite
- raw.records 7개 (1/13 4개, 1/17 3개), 저장 rows 7개. 변환 과정에서 사라진 운동은 없었다.
- raw.unparsed에는 “판독량이 많아 1/21 이후 기록은 본 JSON에 포함되지 않음”이 들어 있었다.
- 사용량: 입력 3,965 / 출력 1,499토큰. 코드의 extraction 출력 상한은 32,768이다.
- gemini 어댑터는 finishReason STOP만 허용한다. 유효한 JSON을 끝냈다는 것이 사진 전체를 읽었다는 증거는 아니다.
- 실제 원본에는 이후 날짜들이 더 있다. 모델이 그 부분을 실제로 읽었는지는 반환 응답만으로 증명할 수 없다.

## 구조상 원인과 한계

1. startImport는 사진 전체를 한 번에 전달해 운동별 필드가 많은 JSON을 요구한다. 각 운동에 날짜, 회원명, 측정 종류 및 적용되지 않는 단위 필드가 반복된다. 이것이 생략에 미치는 정도는 모델 비교 실험이 필요하다.
2. parser는 필드 형식과 최대 개수를 검사하지만 원본 날짜별 누락 여부를 확인하지 않는다. 7개만 반환해도 유효하다.
3. unparsed는 page/text/reason뿐이다. 독립 수업으로 표시할 날짜와 영역 정보가 없고, 전체 누락과 모호한 글자를 구분하지 못한다.
4. 원문 연도 null에 서버가 기본 연도를 넣고 yearConfirmed=true로 처리한다. 안내문은 연도를 물어도 카드에는 확정 날짜처럼 보인다.
5. 회원명 누락과 재판독 중복 확인이 운동마다 반복된다. 재판독에서 ID가 새로 생긴 항목은 실제 동일 운동 후보 여부와 관계없이 경고를 받는다.
6. 세트 없는 운동은 초안으로는 남지만 validInput이 측정값을 요구하므로 수치 없는 수행 이력을 확정하는 별도 상태가 없다.

## 이번 화면 수정

- 재판독 처리 및 결과 안내를 기록수정 내용 영역 전체에 표시. 결과는 확인 버튼 또는 기존 4초 타이머로 닫힌다.
- 파일 전체 확인 목록을 날짜 카드 밖으로 이동하고 운동별 날짜를 표시.
- 파일의 unparsed 개수를 모든 수업의 수정 개수에 중복 합산하지 않는다.
- unparsed가 남으면 “일부 판독 · 미반영 내용 있음”으로 표시. 형식상 성공을 “판독 완료”로 단정하지 않는다.

## 다음 구현 순서

1. 날짜별 영역 목록을 먼저 추출한다. 연도 미상은 연도 미상으로 보존한다.
2. 영역별로 운동과 원문을 추출하고 모든 영역의 처리 결과를 추적한다. 사진은 한 원본을 공유하고 수업 데이터만 나눈다.
3. 누락 영역만 제한된 횟수로 재시도한다. 최대 호출 수와 토큰 사용량을 기록해 비용을 통제한다. 모델의 영역 목록 자체도 누락 가능하므로 사용자 확인을 제공한다.
4. 수치 없는 운동, 일부 수치만 있는 운동, 측정이 완전한 운동을 구분한다. 수치가 없는 기록은 운동 이력에 보존하되 볼륨·증량 판단 근거로 사용하지 않는다. 저장 검증·Firestore rules·분석 경로를 함께 바꿔야 한다.
5. 동일 사진과 기대 날짜/운동 목록으로 모델별 누락률, 수정 횟수, 시간, 비용을 비교한다.

이 조사에서는 운영 데이터를 수정하거나 새 유료 판독 요청을 실행하지 않았다. 판독 파이프라인 재설계와 기본 연도 동작은 이번 UI 수정에 포함하지 않았다.
